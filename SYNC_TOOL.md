# Работа с репозиторием — обязательная инструкция

Читать перед любой задачей и после восстановления контекста. Чтение не запускает команды. Полные параметры, JSON, продолжения и разбор ошибок — в [справочнике](versions/0.1.0/dev-support/qa/SYNC_CLI_REFERENCE.md); читать его только для Git-задачи или конкретного исключения.

## Режим

Сейчас только локальная работа: compare/pull/push/resume и расписание — лишь по новому прямому поручению получить или отправить изменения. Канонический режим — [GITHUB_WORKFLOW](versions/0.1.0/dev-support/project-docs/GITHUB_WORKFLOW.md#auto-push). status/history/save/task/plan работают локально и для обычной игровой задачи достаточны.

## Границы

Агент передаёт скрипту действие, задачу и согласованный состав; Git-команды вручную не дублирует. Секреты, чужие незавершённые изменения и частные commits не отправлять. Один владелец файла и индекса во время операции; файлы, которые скрипт проверяет, не редактировать. add --all/reset/stash/rebase/force push для обхода ответа скрипта не применять.

## Маршрутизация

| Ситуация | Команда |
|---|---|
| Понять состояние | `npm run sync:status` |
| Что было раньше | `npm run sync:history -- --limit 10` |
| Сохранить этап локально | `npm run sync:save -- --task T --message M --file PATH` |
| Готовая задача | `sync task register` → `task ready` → `plan` → `publish --plan PLAN_ID` |
| Разобрать конфликт | править `workspace` из отчёта, затем `sync publish --continue OPERATION_ID` |
| Только локальное разрешение | `sync resolve --operation OPERATION_ID` (без push) |
| Запретить сеть | `npm run sync:pause` (снятие — только по прямому поручению) |

Обычная цепочка выполняется скриптом до результата: агент подключается на конфликте, уточнении состава или ошибке, требующей решения.

## Состав порции

Порция — точные относительные файлы одной задачи, включая удаления и обе стороны переименования. Изменения внутри указанного файла считаются согласованными целиком; смешанные чужие фрагменты сначала разделить. Неопубликованные предки без метки `Task` требуют просмотра: одобрять весь список не глядя нельзя. План фиксирует SHA, fingerprints и свои checkpoints; после изменения файлов или `HEAD` он устаревает, и молча расширять его нельзя.

## Остановки

`conflict` — исходные файлы не объединены, править только сохранённый workspace. `checks-failed`, `verification-failed`, `changed`, `dirty`, `approval-required`, `scope-required`, `ownership-conflict`, `plan-stale`, `paused`, `busy`, `remote-busy` — прочитать `reason` и отчёт, устранить названную причину, не повторять команду циклически. Успешной считается только `pushed`: он подтверждает наличие commit в прочитанной удалённой истории.

## Учёт

Общий Git-каталог: `gamejam-sync/journal.jsonl`, `status.json`, `operations/ID/report.json`, `tasks/`, `plans/`. Журнал не коммитится. Итог команды — короткая сводка; доказательная база остаётся на диске.
