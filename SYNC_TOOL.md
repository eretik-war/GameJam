# Работа с репозиторием — обязательная инструкция

Перед любой задачей и после восстановления контекста прочитать этот файл целиком. Чтение не означает запуск проверки. Скрипт находится в проекте: tools/sync.mjs; реализация — sync-engine.mjs и sync-support.mjs. Один и тот же набор файлов используют оба участника.

## Режим и границы

Сейчас GitHub приостановлен по указанию пользователя: только локальная работа. Не запускать compare/pull/push/resume и расписание без нового прямого поручения получить/отправить изменения. Каноническое разрешение — [GITHUB_WORKFLOW](versions/0.1.0/dev-support/project-docs/GITHUB_WORKFLOW.md#auto-push). status/history/save работают локально. При обычной игровой задаче сетевые команды не нужны.

Агент передаёт скрипту действие, задачу и согласованный состав; Git-команды вручную не дублирует. Исключения разбирает по отчёту. Секреты, чужие незавершённые изменения и частные commits не отправлять. Один владелец файла/индекса во время операции; не редактировать её файлы, пока скрипт их проверяет.

## Команды из корня проекта

На Windows при блокировке npm.ps1 использовать npm.cmd. Node.js 22+, Git и личные user.name/user.email каждого участника; для сети нужна его авторизация GitHub.

| Команда | Действие |
|---|---|
| `npm run sync:status` | Локальное состояние, пауза, lock и последний результат. Удалённые сведения — снимок прошлого fetch |
| `npm run sync:history -- --limit 10` | Последние операции: кто, задача, commits, результат и путь к отчёту |
| `npm run sync:save -- --request work/packet.json` | Локальный checkpoint только перечисленных файлов, без сети; не объявляет тесты пройденными |
| `npm run sync:compare` | По прямому запросу: получить origin/main и записать всю входящую/исходящую порцию с авторами |
| `npm run sync:pull` | По прямому запросу: получить и объединить всю порцию без текстовых конфликтов, проверить и обновить локальную main |
| `npm run sync:push -- --request work/packet.json` | Сохранить выбранные файлы, объединить входящее, проверить и отправить согласованную порцию |
| `npm run sync -- resolve --operation ID` | После разбора конфликта: завершить и проверить подготовленное разрешение в сохранённой папке, применить локально; без push |
| `npm run sync:pause` | Запретить сеть нашим командам во всех worktree этой копии |
| `npm run sync:resume` | Только по прямому поручению снять запрет. Само не обращается к сети и не включает расписание |

Сетевые изменения и save выполняются только на main, отслеживающей origin/main. Для сохранения чужой feature-ветки не переключать её автоматически. Фоновая Windows-задача сейчас отключена; её старый путь остаётся только fast-forward без auto-merge, commits и push.

## Явный состав публикации

Агент готовит JSON со списком **точных относительных файлов** одной готовой порции, включая удаления и обе стороны переименования. Каталоги, glob, .git, ignored-файлы и обходы путей не допускаются. Изменения внутри указанного файла считаются согласованными целиком; смешанные чужие фрагменты сначала разделить.

```json
{
  "taskId": "npc-visuals",
  "actor": "ereti",
  "message": "Обновил согласованные визуалы NPC",
  "files": ["src/example.ts", "assets/example.png"],
  "commits": [],
  "expectedHead": "полный локальный SHA из compare/status",
  "expectedRemote": "полный удалённый SHA из compare",
  "expectedFiles": "fileSnapshot из compare с тем же списком files"
}
```

Пути и SHA в примере — placeholders; заменить реальными, отсутствующие необязательные expected-поля удалить. Чтобы закрепить проверяемое содержание, compare принимает те же `--file` и возвращает fileSnapshot; expectedFiles защищает от правок между просмотром и отправкой. `files` не включает чужие файлы. Если уже есть локальные commits, которых нет в удалённой main, скрипт возвращает approval-required: просмотреть всю историю порции и перечислить только действительно согласованные полные SHA в `commits`. Он не исключает запрещённого предка из истории автоматически. Нельзя обходить этот ответ простым одобрением всего списка без просмотра. Для чистой истории без новых файлов допустимы пустые files и список согласованных commits.

## Результаты и действия

- `compared`, `saved`, `current`, `updated`, `pushed` — соответствующий шаг выполнен. Только pushed подтверждает присутствие отправленного commit в прочитанной удалённой истории; более поздние commits товарища допустимы. current не означает новый прогон тестов.
- `paused`, `busy`, `dirty`, `scope-required`, `approval-required`, `changed` — прочитать message/report и устранить только названную причину. Не применять add --all/reset/stash/rebase/force push для обхода. Новая правка во время проверки останавливает отправку.
- `conflict` — исходные рабочие файлы не объединены. Открыть report и указанный workspace, согласовать текст/двоичный файл, отредактировать только конфликтующие файлы там. Затем resolve с ID исходной операции; скрипт выполнит Git-оформление и проверки. Публикацию после этого запрашивать отдельно.
- `checks-failed`, `error`, `verification-failed`, `remote-busy` — отправку успешной не считать. Local checkpoint сохраняется, полный отчёт/кандидат доступны. Разобрать конкретный сбой; циклически не повторять команды без причины.

Скрипт делает не более трёх попыток публикации при одновременном push. Новый объединённый состав проверяется заново; одинаковое дерево повторно проверяется только один раз внутри одной операции. Проверки идут в изолированном worktree. Игровая порция запускает check:game (типы, модель, сборка, validate); изменения sync-инструмента, validate, package/lock, CI или этой инструкции запускают полный check с Git-тестами. CI всегда выполняет полный check. При неудаче локальный checkpoint уже может существовать — это сохранение работы, не публикация.

## Учёт и подробности

В общем Git-каталоге: gamejam-sync/journal.jsonl, status.json и operations/ID/report.json; там же логи проверок и сохранённые конфликтные папки. Журнал не коммитится и не создаёт конфликтующий общий log-файл. Между машинами авторство передаёт история Git: личный автор, Task и Sync-Operation в новых commits. Состояние другой машины не подтверждается вашим push — она получает изменения при своём вызове sync.

Подробная проверка инструмента — [SYNC_TOOL](versions/0.1.0/dev-support/qa/SYNC_TOOL.md). Точечное чтение, одна общая интеграция и публикация готовой порции — [WORKFLOW](versions/0.1.0/dev-support/project-docs/WORKFLOW.md). Не читать старые архивы и полные логи, если текущий результат не требует их разбора.
