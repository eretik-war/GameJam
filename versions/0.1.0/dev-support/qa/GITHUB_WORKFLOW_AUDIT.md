## Причины и изменения процесса

| Наблюдение | Почему возникает лишняя работа | Что упростить |
|---|---|---|
| Несколько чатов меняют одну папку/main, main.ts и CURRENT_STATE | Общий индекс Git не хранит авторство незакоммиченных фрагментов. Приходится вручную разделять изменения и защищать чужую работу | Одна ветка/worktree на одновременную задачу, один владелец интеграции; общий файл править последовательно |
| Частные NPC совмещены с правилом автоматического push каждой задачи | Для предметов и карточки героя готовились отдельные публичные варианты, затем повторно проверялась общая локальная сцена | Явно отделить локальную интеграцию от согласованной публикации. Не держать непубликуемую историю в ветке, которую другие чаты должны отправлять |
| Локальная история и origin/main разошлись | Fast-forward намеренно не объединяет две линии. Таймер повторяет диагностику, но не устраняет причину | Один ответственный выполняет настоящий merge в точке интеграции. Не ожидать, что очередной sync:pull исправит divergence |
| Функции из GitHub переносились по отдельности в изменённую локальную сцену | Возможны пропущенные связанные изменения: скрытый debug вернули раньше, чем его полноэкранную геометрию; атака интегрировалась отдельным этапом | Один просмотр всей входящей порции: список commits, diff по затронутым подсистемам, конфликты и общий критерий готовности |
| sync:push объединяет fetch, полный check, add --all, commit и push | Удобно для одной чистой задачи; в общей папке может захватить чужие изменения и повторяет уже выполненный check | После возобновления разделить подготовку просмотренного commit и отправку. | Историческое правило требовало Git-статус каждого сообщения; позднее его отменили | Повторная диагностика и повторение правил отвлекают от результата; копии правил могут расходиться | Один канонический активный режим в GITHUB_WORKFLOW, короткие ссылки из входных документов, никаких Git-проверок ради промежуточного ответа |

## Предлагаемый простой порядок после возобновления

1. В согласованной точке получить origin/main один раз. Зафиксировать базовый commit и распределить файлы. Одновременным задачам — отдельные codex/* ветки/worktree; общая main используется для принятой интеграции.
2. Внутри задачи работать локально и проверять изменяемую область. Не опрашивать GitHub после каждого сообщения. Сохранять законченный результат адресным commit; не включать чужие файлы через add --all.
3. Один ответственный объединяет готовые ветки и изменения товарища в общей интеграции. Просматривает весь входящий diff, выполняет нужные проверки общего результата. Новые изменения после проверки требуют повторной проверки затронутого поведения.
4. Отправить принятую порцию один раз и один раз подтвердить удалённый commit. Серверный CI проверять по факту публикации или ошибки, без постоянного опроса. Повторный полный локальный check без изменения проверенного дерева не нужен.

В текущей грязной общей папке этот переход не выполнялся: история не переписана, worktree не переносились, чужие правки сохранены. Сейчас действуют только локальный режим и защита sync-команд. Изменение команды публикации, разделение check на игровой и Git-набор и сокращение накопленного CURRENT_STATE — следующие отдельные улучшения; тесты не удалялись и проверки качества не ослаблялись.

## Как проверить эффект

На следующей сопоставимой законченной задаче снять один baseline/end по thread ID: вход, кеш, некешированный вход, выход, reasoning внутри выхода, blended, время и критерий качества. Отдельно считать обращения к сети, интеграции и повторные полные проверки без изменения дерева. Сравнивать задачи сходного объёма; заранее обещать процент экономии нельзя. Модель и effort в этом аудите не переключались.
