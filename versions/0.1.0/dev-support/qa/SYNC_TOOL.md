# Проверка единого репозиторного скрипта — 2026-10-31

Поручение: перенести детерминированные операции Git в проектный скрипт, учитывать автора/задачу/состав, обрабатывать одновременные push и сделать инструкцию обязательной перед любой задачей. Пользователь выбрал auto-merge без конфликтов с проверкой результата и остановку при конфликте. GitHub проекта и Windows-расписание остаются на паузе.

## Владельцы

- tools/sync.mjs — CLI, структурированный request JSON и краткий ответ; экспорт совместимого sync для тестов.
- tools/sync-engine.mjs — состояние операции, сравнение, checkpoint, изолированная интеграция/проверка, публикация/повтор, локальное разрешение и журнал.
- tools/sync-support.mjs — ограниченные Git-вызовы без shell-интерполяции, чтение файлов, fingerprints, общий lock и запуск npm check с логом.
- [Корневой SYNC_TOOL.md](../../../../SYNC_TOOL.md) — единственная обязательная инструкция использования; ссылки из AGENTS и READ_FIRST проверяет validate.

Старый вызов push с одной строкой сообщения, который делал add --all, намеренно отключён. Новые files — точные пути одной согласованной порции; commits — полные SHA согласованной неопубликованной истории. Другие staged/unstaged файлы не включаются в checkpoint. Внутри одного файла авторство незакоммиченных фрагментов скрипт не угадывает: смешанные изменения сначала разделяет владелец задачи.

## Фиксация и воспроизводимость

В общем Git-каталоге всей копии: gamejam-sync/lock, paused.json, status.json, journal.jsonl и operations/ID/report.json. Операция записывает начало до изменяющих шагов и итог; history объединяет записи по ID. Отчёт содержит реальное Git-имя/email и отдельную метку actor, taskId, исходные SHA и общий base, входящие/исходящие commits с авторами, статусы/режимы/хеши файлов, локальные правки, checkpoint, попытки и проверки точного дерева. Метка actor не подменяет Git-автора. Новые commits получают Task и Sync-Operation.

При аварийном завершении started и последний записанный этап остаются на диске; journal не является гарантией атомарности нескольких файлов или подтверждением удалённого результата. Проверяемые candidates дополнительно удерживаются ссылкой refs/gamejam-sync/operations/ID. Рабочие папки неудачных/конфликтных операций сохраняются; удаляются только собственные чистые папки успешных шагов без force. Журналы не синхронизируются между машинами отдельным общим файлом; общее авторство передаётся историей commits.

## Защита от гонок

Публикация создаёт адресный локальный checkpoint, получает/объединяет входящую историю в изолированном worktree, проверяет именно candidate и лишь затем применяет его fast-forward и отправляет по точному SHA. Локальный checkpoint может остаться после провала теста — это намеренное сохранение работы, не успешный push.

Общий lock охватывает связанные worktree этой копии. Внешние Git-команды и редакторы его не соблюдают автоматически, поэтому HEAD и выбранные файлы дополнительно проверяются перед применением; неожиданные изменения останавливают операцию. Git сам отклоняет несовместимую обычную отправку. При конкурирующем продвижении remote повторяются fetch/merge/check, максимум три попытки по умолчанию (1–5 явно). Проверка одинакового дерева переиспользуется только внутри текущего вызова; между вызовами тестовый кеш не ведётся.

Readback проверяет, что отправленный commit является предком наблюдаемой main. Она может уже содержать следующий commit товарища; равенство HEAD не требуется. При ошибке связи после отправки успешность не предполагается. Последующий запуск получает состояние заново.

При конфликте источник не объединяется: конфликтная папка сохраняется. Агент/участник выбирает содержание, затем resolve проверяет принадлежность workspace, исходную историю и отсутствие оставшихся маркеров/посторонних правок, оформляет merge и запускает проверки. Это локальная операция; она не публикует решение. Для бинарного файла содержание выбирает участник, script не выбирает автоматически «наше/их».

## Проверенные сценарии

tools/sync.test.mjs использует только временные локальные bare-репозитории и две копии участников. Публикации в этих тестах не обращаются к GitHub. Набор покрывает:

- всю входящую/исходящую порцию, blob-хеши, незакоммиченные файлы и авторов;
- проверяемый fast-forward и сохранение обеих линий при чистом merge;
- текстовый/двоичный конфликт без изменения исходника;
- отказ dirty pull, сохранность стороннего staging и неотслеживаемых файлов;
- адресные новые/удалённые/переименованные файлы, Unicode/пробелы и буквальные сообщения;
- остановку перед отправкой частных предков без явного списка commits;
- сохранение checkpoint при сбое проверки, остановку при изменении source/candidate;
- конкурирующий push, повторную проверку изменённого дерева и ограничение повторов;
- повтор без лишней проверки при неизменном дереве;
- более поздний удалённый child commit после успешной публикации;
- общую паузу/lock, локальный save во время паузы и pause/resume без сети;
- остановку push при паузе во время проверок;
- resolve после разбора конфликта, без удалённой публикации;
- реальный запуск npm check в candidate и сохранение лога;
- запрет traversal, .git, ignored-файлов и junction/symlink;
- CLI request JSON, явные пути, отсутствие shell-интерполяции и защиту от устаревшего согласования.

Итог полного прогона фиксируется в текущем состоянии и сыром локальном отчёте work/sync-tool-verification/final-check.log. Для этой инструментальной доработки выполняются npm run check и локальные проверки CLI/паузы; игровые исходники/ресурсы не изменялись, повторный браузерный сценарий игры не требуется. Реальный remote GameJam не запрашивался и не изменялся.

Чтобы не повторять тяжёлый Git-набор на каждой игровой порции, script выбирает check:game (typecheck, модель, offline build, validate), если общий состав не затрагивает sync-файлы, validate, package/lock, CI и обязательную инструкцию. Для этих файлов и при отсутствии отдельного игрового профиля используется полный check. Это проверено публикацией двух реальных fixture-порций с разными npm-профилями и чтением их логов. GitHub CI по-прежнему запускает полный check; тесты из него не исключались.

## Границы

Текстовое объединение без конфликта не доказывает игровую совместимость; нужна проверка общей порции. Скрипт не может обновить другую машину, пока там не вызвали синхронизацию. При source-правках, ошибке сети, hooks, тестов или конфликте он возвращает остановку и отчёт вместо выбора по дате, силы или бесконечного повторения. Форсированная смена чужой удалённой истории, rebase/reset/clean/stash, deploy, удаление веток и автоматический запуск расписания в него не включены.
