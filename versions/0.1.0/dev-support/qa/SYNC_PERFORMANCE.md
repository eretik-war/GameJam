# Замеры репозиторного скрипта — 2026-10-31

Цель доработки: обычная публикация одной командой по готовой задаче, один прогон проверок для неизменного итога, короткая обязательная инструкция и предсказуемый вывод. Сырые данные — в `<общий Git-каталог>/gamejam-sync/bench/*.json`; здесь только сводка.

## Условия

Windows 10.0.26100 x64, Node v22.22.2, Git 2.55.0.windows.3. Все сценарии — временные локальные репозитории с двумя участниками; реальный remote не запрашивался. Проверки в замере заменены счётчиком, поэтому времена показывают стоимость протокола, а не длительность `npm run check`. Длительность реального полного прогона в базовом отчёте: около 128 с на дерево.

Команда: `npm run bench:sync -- --fixture template --repeats 3`.

## Что именно изменилось

1. **Одна проверка неизменного итога.** Разбор конфликта, проверка candidate, применение и публикация разделены на шаги. Продолжение `publish --continue` оформляет разрешение, проверяет итог и отправляет его в одном вызове. Отдельный `resolve` остаётся локальным.
2. **Подтверждение проверки.** Записываются точный commit и дерево, профиль и его состав, версия инструмента и fingerprint, Node/Git/ОС, хеши `ENGINE_LOCK.json` и `package-lock.json`, `installId` установки зависимостей, лог и время. Переиспользование возможно только в цепочке операции при полном совпадении; неуспешное подтверждение не переиспользуется.
3. **Реестр задач и планы.** Владелец файлов фиксируется явно, план замораживает SHA, fingerprints и собственные checkpoints. Устаревший план, чужой файл и непросмотренный предок останавливают публикацию.
4. **Короткий вход.** Обязательная инструкция сокращена с 10,4 КБ до 4,5 КБ (37 строк); полные параметры вынесены в справочник и читаются только для Git-задачи. `validate` следит за бюджетом объёма.
5. **Компактный вывод.** Итог — 8–12 строк; полные diff, авторство, fingerprints и логи остаются на диске. Этапы идут в stderr, поэтому `--json` остаётся разбираемым.
6. **Быстрые тестовые репозитории.** Неизменяемый шаблон создаётся один раз за прогон, каждый сценарий получает копию со своими refs, index, рабочими файлами и bare remote; `origin` переназначается. Очистка ограничена каталогами с префиксом `GameJam-sync-tests-` в системном временном каталоге.

## Чего не сделано и почему

- **Число Git-процессов обычной публикации выросло на 5.** Это цена записи подтверждения проверки (fingerprint инструмента, среда, дерево). Сокращать адаптер дальше без измерения не требуется.
- **Экономия токенов не объявляется.** Сопоставимый прогон одной задачи на одной модели и effort не выполнялся, поэтому проценты не приводятся. Детерминированные заменители: вывод CLI уменьшился вдвое, а число ручных шагов агента (сборка JSON, перенос SHA и fingerprints, чтение промежуточных отчётов) сократилось до одной команды на шаг.
- **Параллельный запуск тестов не включён.** `execFileSync`/`spawnSync` блокируют процесс Node; без переписывания адаптера флаг concurrency не даёт выигрыша. Сначала измерена подготовка репозиториев, она и ускорена.
- **Реальный push и расписание** в замеры не входят и выполняются только по прямому поручению пользователя.

## Границы

Замер описывает протокол, а не игровую совместимость. Текстовое объединение без конфликта её не доказывает: общую порцию всё равно просматривает ответственный, а игровое изменение требует браузерной проверки.
