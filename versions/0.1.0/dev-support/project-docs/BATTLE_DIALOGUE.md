# Диалоги перед боем и реплики при уроне

## Поведение

Только в самом первом бою прохождения появляются три тестовые реплики: камера → герой → камера. Говорит первый живой развёрнутый противник, а не резерв и не NPC из предыдущего боя. Имя берётся из EnemyInfo.Name; у героя — из его справочника. Каталог камер уже содержит «Бирюзовый младший брат», «Розовый младший брат», «Голубой младший брат», «Жёлтый младший брат». Стабильные typeId и instance ID не менялись.

Тестовый разговор:

1. Камера: «Старший брат, ты всё-таки пришёл! Мы тебя ждали.»
2. Герой: «Младшие, отойдите. Я не хочу вас ломать.»
3. Камера: «Не можем, старший брат. Нам велели тебя остановить.»

ЛКМ заменяет предыдущую реплику следующей. После третьей ещё один ЛКМ закрывает разговор; этот же клик не атакует. ПКМ, Enter и Пробел его не листают. Пока идёт разговор, атаки и клики по нижележащему интерфейсу блокируются. Сцена продолжает анимироваться. Общая последовательность боёв/катсцен принадлежит другому владельцу и здесь не переписывается.

При фактическом уменьшении здоровья или щита NPC появляется «Не бей нас, старший брат!». Отмена атаки, промах и оглушение без урона реплики не создают. Реплика остаётся полностью непрозрачной 2000 мс активного боя, затем линейно исчезает за 1000 мс и удаляется. Кликами её закрыть нельзя; она не перехватывает мышь. Повторный урон тому же NPC обновляет одно облачко и начинает его срок заново. Разные NPC могут говорить одновременно; смертельный удар тоже допускает последнюю реплику.

## Владельцы

- `src/domain/battle-dialogue.ts`: замороженные тестовые тексты, привязка к боевым instance ID, текущая реплика, наблюдение реальных изменений параметров вокруг действия, таймер и прозрачность. Модель не зависит от DOM/Pixi и не повторяет формулы урона.
- `src/battle-dialogue-controller.ts`: единое DOM-представление имени/текста, захват ввода вступления, согласование облачков и освобождение подписок.
- `src/main.ts`: передаёт действующие EnemySession и реальные bounds героя/камер из renderer, оборачивает атаки/debug-действия в perform, обновляет модель elapsedMS тикера и подключает lifecycle сцены.
- `src/style.css`: absolute-слой поверх существующего canvas. Ничего не резервирует в раскладке; при изменении настольного окна облачко следует за говорящим и ограничивается границами сцены.

Новый бой получает новую модель диалога, но начиная со второго боя вступление отключено: можно атаковать сразу, а реплики при уроне продолжают работать. Флаг battleIntroShown в main.ts отмечает первый запуск вступления и сбрасывается при новом прохождении через restart; debug-preview не сбрасывает его. Debug-загрузка снимка получает новую модель без повторного вступления и без облачков прежней сессии. При показе катсцены/переходе слой скрывается; в debug-preview прогресс существующего разговора сохраняется. Время реплик не идёт, пока бой скрыт/тикер остановлен. Схема сохранения боя не менялась; разговор и временные реплики не сохраняются.

Для замены тестового текста редактировать openingLines и текст hit в domain/battle-dialogue.ts. Не копировать их в main.ts или DOM-контроллер. Отдельные разговоры по уровням, случайные наборы боевых реплик и сохранение разговора пока не реализованы.

## Проверки

`tests/battle-messages.test.ts` подключён к общему прогону через domain.test.ts. Его явная расстановка двух камер не зависит от текущих параллельных правок кампании.

Браузерная проверка: `node tools/verify-battle-dialogue.mjs`; временный Chrome-профиль можно перенаправить переменной GAMEJAM_QA_SCRATCH. На Windows этого прогона использовано C:/Users/ereti/AppData/Local/hermes/cache/scratch. Для file-проверки сначала выполнить npm run build:offline.

Фактически прошли:

- npm run typecheck;
- npm test: 50 тестов, включая пять тестов модели диалогов и проверку четырёх имён;
- npm run build:offline и npm run validate;
- Chrome HTTP и отдельный file://, 1280×720 и 1440×900: три реплики/имена, ПКМ не листает, клики по врагу во вступлении не атакуют, финальный клик не атакует, последующая атака создаёт hit, пустой клик не закрывает hit, удержание/прозрачность/удаление, неизменный размер canvas, resize, debug load, отсутствие вступления во втором бою и немедленная атака с боевой репликой;
- runtime exceptions: 0; file-сборка не сделала HTTP-запросов;
- git diff --check.

Доказательства: `builds/battle-dialogue-verification.json`, `builds/battle-dialogue-http-npc.png`, `battle-dialogue-http-hero.png`, `battle-dialogue-http-1440.png` и соответствующие file-снимки. Проверки опираются на DOM, настоящий мышиный ввод Chrome и состояние игры; автоматическая интерпретация изображений не была доступна. Скриншоты не ставятся между измерениями трёхсекундной реплики: программный WebGL может тратить на захват больше самого срока облачка.

При восстановлении предыдущего чата обнаружены заглушка BattleDialogueSession, тест вступления и уже переименованные камеры. Заглушка заменена рабочей моделью и подключена к игре. Одновременно другие чаты меняли предметы и кампанию и удалили прежний тест; пользователь поручил продолжать отдельно и не исправлять их файлы. Их изменения сохранены; GitHub не использовался. Проверки выше относятся к совместному состоянию на момент прогона и должны повторяться после следующих чужих изменений.
