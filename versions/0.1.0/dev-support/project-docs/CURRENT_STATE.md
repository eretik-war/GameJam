# Текущее состояние GameJam

Актуально на 2026-10-31. Активная версия и пути — PROJECT_MANIFEST.json. Работаем только над компьютерной версией.

## Цель и разрешения

Реализован единый проектный tools/sync.mjs: сравнение, адресный checkpoint, интеграция, проверки, push/повтор и журнал выполняются скриптом; агент задаёт действие и разбирает исключения. Обязательная перед любой задачей инструкция — [SYNC_TOOL.md](../../../../SYNC_TOOL.md), ссылки закреплены в AGENTS/READ_FIRST и validate. Один набор файлов предназначен обоим участникам. Приняты точечное чтение, краткое состояние/отчёты, одна общая интеграция и публикация готовой порции — [WORKFLOW](WORKFLOW.md). Auto-merge без конфликтов с проверками; при конфликте остановка и локальный resolve после разбора файлов.

2026-10-31 пользователь прямо поручил пробный push готового результата этого чата: NPC/бой, ресурсы, sync-инструмент и документация. Разрешена эта ручная публикация с проверкой входящей порции и истории; чужое незавершённое standards/INFO_OBJECT_RULES.md исключено. Канонический режим — [GITHUB_WORKFLOW](GITHUB_WORKFLOW.md#auto-push). Windows GameJam-Sync-95E2E963735A остаётся Disabled, автоматическая отправка не возобновляется; после операции возвращается локальная пауза. Не применять force push/reset --hard/clean/автоматический stash/rebase.

## Инструменты и проверки

CLI — sync.mjs, автомат состояний/журнал — sync-engine.mjs, Git/файлы/lock/проверки — sync-support.mjs. main/origin-main; request JSON задаёт точные files и согласованные commits. Частная неопубликованная история требует отдельного явного списка. Общая пауза/lock, изолированный candidate, до трёх повторов при гонке, readback по наличию commit в удалённой истории. Checkpoint при сбое сохраняется. Журнал хранится в общем Git-каталоге; авторы и Task/Sync-Operation — также в commits. Игровая порция использует check:game; инструмент/package/lock/CI/инструкция — полный check.
