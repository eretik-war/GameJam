Реализован единый проектный tools/sync.mjs: сравнение, адресный checkpoint, интеграция, проверки, push/повтор и журнал выполняются скриптом; агент задаёт действие и разбирает исключения. Обязательная перед любой задачей инструкция — [SYNC_TOOL.md](../../../../SYNC_TOOL.md) (37 строк), полные параметры — [справочник скрипта](../qa/SYNC_CLI_REFERENCE.md); ссылки закреплены в AGENTS/READ_FIRST и validate. Один набор файлов предназначен обоим участникам. Приняты точечное чтение, краткое состояние/отчёты, одна общая интеграция и публикация готовой порции — [WORKFLOW](WORKFLOW.md).

2026-10-31 пользователь поручил реализовать план ускорения целиком и затем пробную публикацию готовой порции этого чата. Разрешена эта ручная публикация с проверкой входящей порции и истории; чужое незавершённое standards/INFO_OBJECT_RULES.md исключено. Канонический режим — [GITHUB_WORKFLOW](GITHUB_WORKFLOW.md#auto-push). Windows GameJam-Sync-95E2E963735A остаётся Disabled, автоматическая отправка не возобновляется; после операции возвращается локальная пауза. Не применять force push/reset --hard/clean/автоматический stash/rebase.

## Инструменты и проверки

CLI и компактный вывод — sync.mjs, шаги операции/продолжение/проверки/журнал — sync-engine.mjs, Git/файлы/lock/профиль/среда — sync-support.mjs, реестр задач и планы — sync-tasks.mjs. Готовая задача описывается явно: `task register` → `task ready` → `plan` → `publish --plan`. Разобранный конфликт закрывается одним `publish --continue`: оформление, проверка и отправка в одном вызове; `resolve` остаётся локальным. Подтверждение проверки привязано к commit, дереву, профилю, версии инструмента и среде и переиспользуется только в цепочке операции. main/origin-main; частная неопубликованная история по-прежнему требует явного списка commits. Общая пауза/lock, изолированный candidate, до трёх повторов при гонке, readback по наличию commit в удалённой истории. Checkpoint при сбое сохраняется. Журнал, реестр задач и планы хранятся в общем Git-каталоге; авторы и Task/Sync-Operation — также в commits. Игровая порция использует check:game; инструмент/package/lock/CI/инструкция — полный check.

Последняя игровая проверка — [COMBAT_INTEGRATION](../qa/COMBAT_INTEGRATION.md). Инструмент — [qa/SYNC_TOOL](../qa/SYNC_TOOL.md); локальные временные репозитории двух участников строятся из одного шаблона. Финальный npm run check прошёл: typecheck, 21 тест модели, 39 тестов синхронизации, offline build и validate. Замеры до/после — [SYNC_PERFORMANCE](../qa/SYNC_PERFORMANCE.md): один прогон проверок вместо двух на неизменном итоге конфликта, подготовка тестового репозитория 831 мс/7 Git-процессов вместо 1448 мс/14, вывод CLI 8 строк вместо 18.
