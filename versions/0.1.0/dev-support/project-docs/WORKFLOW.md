# Рабочий процесс

## Постановка

Зафиксировать цель, наблюдаемое поведение и критерий готовности. Разделять подтверждённые требования, предположение и предложение. Пользователь может сразу поручить реализацию обычными словами; повторное разрешение на уже порученную обратимую работу не требуется. Не утверждать жанр, экономику или платформу из технического примера.

## Итерация

1. Перед любой задачей/после восстановления прочитать обязательный [SYNC_TOOL.md](../../../../SYNC_TOOL.md) и активный режим GITHUB_WORKFLOW. Сейчас GitHub приостановлен; работать локально. По READ_FIRST/индексу найти владельца области, связанные контракты и потребителей; читать только затронутую область.
2. Уточнить только блокирующую неопределённость; независимую работу продолжать. Сложную задачу разбить на проверяемые шаги, обозначить влияние на сохранения, общие формулы и UI.
3. Реализовать небольшой законченный путь в исходниках. Переносимую инфраструктуру сперва проверять в игре; не объявлять общей без согласования и второго контекста.
4. Проверить изменённую область, модель и сборку; при игровом изменении открыть настольный браузер, проверить мышь/клавиатуру и resize. Не заменять наблюдение за поведением одним успешным npm build. Документация/инструмент требуют соответствующих проверок; повторный игровой прогон без изменения игры не нужен.
5. По завершении обновить документы затронутых контрактов и краткий CURRENT_STATE. Передать: что изменилось, как проверено, ограничения и путь к результату. Во время локального режима не делать удалённую проверку или push; локальный commit по необходимости включает только свои правки. Не повторять успешные проверки без последующих изменений или новой причины.

## Работа вдвоём

До одновременных изменений договориться о владельцах: например, domain/баланс и presentation/ресурсы. В задаче указать входы/выходы и файлы. Один файл в момент времени меняет один человек/агент. Enum, формат Info и save schema — общие контракты; менять их вместе с потребителями и проверками. GitHub временно приостановлен. Перед правками учитывать локальные изменения других участников. Одновременным задачам выделять отдельные ветки/worktree; общую интеграцию и проверку выполняет один ответственный. Текущий режим и возобновление — [GITHUB_WORKFLOW](GITHUB_WORKFLOW.md).

## Принятые упрощения — 2026-10-31

- Читать точечно по READ_FIRST → индекс → владелец области. CURRENT_STATE содержит только актуальную цель, разрешения, состояние, проверки и следующий шаг; подробности и прошлые этапы остаются в отчётах/архиве по ссылкам. Не дописывать историю каждой задачи в начало рабочего состояния.
- Выполнять одну общую интеграцию с просмотром всей входящей порции: commits и все изменённые/добавленные/удалённые файлы, связанные ресурсы и контракты. Проверять объединённый результат; не переносить опубликованные функции по одной без учёта остальных входящих изменений.
- Публиковать согласованную готовую порцию с явным составом и проверками. Локальное сохранение этапа и промежуточное сообщение не запускают публикацию. Текущая пауза GitHub сохраняется; правила не являются поручением отправить существующие изменения.

Репозиторный скрипт tools/sync.mjs выполняет согласованный auto-merge без конфликтов с проверкой результата; при конфликте сохраняет workspace и отчёт, resolve оформляет уже разобранное решение локально. Агент задаёт действие и согласованный пакет через request JSON; обычные Git-шаги вручную не дублирует. Сетевые команды по-прежнему требуют прямого поручения пользователя.

## Версии и разрешения

Манифест определяет активную папку. Версии движка/сборки фиксируются и проверяются; latest не заменяет отсутствующую зависимость. Игра и сборка переносимы. Идеи не являются реализацией; явное поручение разрешает нужные изменения. Новая версия проекта, deploy, публикация, удаление старых копий и массовые миграции — отдельные решения. Общие правила сами по себе не переписывают существующие игры.

## Передача следующему чату

CURRENT_STATE: цель, разрешённый объём, принятые решения, рабочие файлы, выполненные проверки, незакрытые риски, следующий шаг и ссылки на артефакты. Обновлять текущее состояние вместо накопления прежних сводок. Исторический архив не входит в обычное чтение; открывать только для конкретного вопроса о прошлом. Индекс и CODE_MAP обновлять при изменении маршрутов или владельцев.
