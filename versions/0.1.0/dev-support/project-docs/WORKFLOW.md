# Рабочий процесс

## Постановка

Зафиксировать цель, наблюдаемое поведение и критерий готовности. Разделять подтверждённые требования, предположение и предложение. Пользователь может сразу поручить реализацию обычными словами; повторное разрешение на уже порученную обратимую работу не требуется. Не утверждать жанр, экономику или платформу из технического примера.

## Итерация

1. При каждом входе/ознакомлении/восстановлении чата прочитать [постоянное разрешение на отправку и итоговую Git-проверку](GITHUB_WORKFLOW.md#auto-push). По READ_FIRST/индексу найти владельца области, связанные контракты и потребителей. Для общего знакомства прочитать базовый набор; для конкретной задачи — предметную область.
2. Уточнить только блокирующую неопределённость; независимую работу продолжать. Сложную задачу разбить на проверяемые шаги, обозначить влияние на сохранения, общие формулы и UI.
3. Реализовать небольшой законченный путь в исходниках. Переносимую инфраструктуру сперва проверять в игре; не объявлять общей без согласования и второго контекста.
4. Проверить модель и сборку; открыть реальный экран, проверить мышь/палец и resize. Не заменять наблюдение за поведением одним успешным npm build.
5. После каждой завершённой доработки обновить относящиеся к ней документы и CURRENT_STATE, сразу выполнить commit/push по постоянному разрешению пользователя и проверить удалённый результат. Передать: что изменилось и зачем, как проверено, реальные ограничения, путь к результату. Проверку удалённого репозитория и один краткий фактический статус включать в завершение задачи. Не запускать Git и не добавлять статус в каждое промежуточное сообщение; во время реализации уделять внимание локальному результату. При неуспешной отправке указать причину и оставшиеся локальные изменения.

## Работа вдвоём

До одновременных изменений договориться о владельцах: например, domain/баланс и presentation/ресурсы. В задаче указать входы/выходы и файлы. Один файл в момент времени меняет один человек/агент. Enum, формат Info и save schema — общие контракты; менять их вместе с потребителями и проверками. Git/GitHub подключены по запросу пользователя от 2026-10-30. Перед правками учитывать локальные изменения других участников. Получение и отправка — при завершении задачи либо по прямому запросу пользователя; команды: npm run sync:pull и npm run sync:push -- "Описание". Автополучение работает только с чистым main и не объединяет разошедшиеся commits. Полная инструкция: [GITHUB_WORKFLOW](GITHUB_WORKFLOW.md).

## Версии и разрешения

Манифест определяет активную папку. Версии движка/сборки фиксируются и проверяются; latest не заменяет отсутствующую зависимость. Игра и сборка переносимы. Идеи не являются реализацией; явное поручение разрешает нужные изменения. Новая версия проекта, deploy, публикация, удаление старых копий и массовые миграции — отдельные решения. Общие правила сами по себе не переписывают существующие игры.

## Передача следующему чату

CURRENT_STATE: цель, разрешённый объём, принятые решения, рабочие файлы, выполненные проверки, незакрытые риски, следующий шаг и артефакты. Хранить кратко; большие логи оставить в dev-support/qa. Индекс и CODE_MAP обновлять при изменении маршрутов или владельцев.
