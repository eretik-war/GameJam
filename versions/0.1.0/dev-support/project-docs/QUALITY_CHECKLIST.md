# Готовность изменения

- Модель: Info и вложенные параметры неизменны; две копии независимы; enum разных доменов не смешиваются; неизвестные/дублирующиеся ключи и ID отвергаются. Модификатор применяется один раз, все окна используют один результат.
- Действия: допустимость проверяется до изменения; пошаговая логика не зависит от FPS; предмет/ресурс не теряется и не дублируется при ошибке. Проверять затронутые границы, а не повторять реализацию тестами.
- Сохранение: round-trip IDs/параметров/выбора; неверная схема или данные не заменяют текущую сессию; миграции и совместимость явные.
- Инструменты: npm run typecheck, npm test, npm run validate, npm run build:offline. На важных границах добавить содержательные проверки.
- Браузер: компьютерная версия, реальный WebGL canvas, действия/поля, выбор мышью/клавиатурой, save/load и resize настольного окна; нет ошибок console/pageerror. Мобильная адаптация, телефонные размеры/ориентации и touch-проверки пока не требуются: [область работ](MOBILE_UI_ASSETS.md). HTTP и прямой file:// указывать отдельно. Готовый файл проверить из отдельной папки, без соседних assets/Foundation.
- Ресурсы: границы кадров/alpha, память, реальный размер, лицензии/credits, музыка после жеста/видимость. В offline нет внешних запросов или обязательных соседних файлов.
- Передача: указать артефакт и проверки, незакрытые ограничения. При изменении маршрутов обновить индекс/карту; текущее состояние — отдельно. Ручная проверка человеком остаётся частью принятия игрового поведения.

Платформенная публикация не настроена. После выбора площадки отдельно подключить provider/capabilities, проверку рекламы/lifecycle/облака и release allowlist; публикация требует команды. Для неоднозначной Yandex-сборки уточнять «С модулем тестирования или без?». Тестовый модуль не попадает в production/другие платформы.
