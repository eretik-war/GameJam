# Герой: положение и idle-анимация

Прямое поручение пользователя 2026-10-30: заменить временного героя тремя предоставленными кадрами Stand1.png, Stand2.png, Stand3.png, разместить в красной области референса и проигрывать полный цикл за 0,5 секунды.

Оригинальные прозрачные PNG скопированы без изменения пикселей в assets/images/hero. Все три файла имеют холст 548×1025; SHA-256 и источник записаны в RESOURCE_REGISTRY. images.ts встраивает их в автономный HTML. Старая тестовая картинка не удаляется, но больше не используется для героя на сцене.

Владелец визуальной композиции — src/presentation/hero-animation.ts: пути кадров, длительность всего цикла, единая область обрезки прозрачных полей, создание AnimatedSprite и положение по пропорциям отмеченной области. Общая область — объединение ненулевой альфы всех трёх кадров; одинаковое кадрирование удерживает ноги на месте и сохраняет естественное движение головы/плаща. Обрезка выполняется UV-прямоугольником текстуры, исходные файлы не переписываются. Положение и размер берутся относительно текущей боевой зоны; пропорции персонажа сохранены.

Порядок цикла: Stand1 → Stand2 → Stand3 → Stand1. Каждому кадру выделена треть общей длительности; 0,5 секунды относится ко всему циклу. Анимация обновляется тикером приложения, а не общим Ticker.shared. Существующая остановка приложения при скрытии страницы останавливает и анимацию. Живой AnimatedSprite принадлежит renderer и сохраняется при перерисовке выбора/статусов, переносах и переключении стадий; повторного старта на каждом render нет. При закрытии уничтожается вместе со сценой.

Это отдельное разрешённое изменение положения героя. Наложение инвентаря по-прежнему не меняет геометрию боевой зоны и остальных юнитов. Проверки: [HERO_ANIMATION](../qa/HERO_ANIMATION.md).

## Последовательные действия в бою — 2026-10-31
По поручению пользователя урон героя применяется перед его движением вперёд-назад (120 мс), затем сразу без паузы выполняется следующее действие. Противники действуют по порядку deployed; недоступные действия пропускаются, успешное лечение тоже получает движение. Только изображение смещается на 2,5% ширины сцены, полоски и раскладка остаются на месте. main.ts владеет движением и паузами через ticker приложения: скрытие страницы приостанавливает последовательность, resize восстанавливает базу и текущее смещение. Ввод инвентаря и повторная атака заблокированы до конца хода; награда проверяется после завершения последовательности.
EnemySession.AttackSequence применяет одно действие на шаг генератора, завершая статусы и ход после ответов; синхронный Attack использует тот же генератор. Модель не зависит от Pixi или таймеров. Проверка: tools/verify-combat-animation.mjs (Chrome desktop HTTP/file, порядок, интервалы, повторный ввод, runtime exceptions), tests/combat.test.ts (пошаговый расчёт совпадает с синхронным).
