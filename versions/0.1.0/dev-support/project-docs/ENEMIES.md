# Противники и статусы

Ассет типа противника: корневой assets/enemies/test-enemy.json. Он задаёт стабильный typeId enemy.trainee (сохранён для совместимости v2), имя, типизированные базовые параметры, изображение/масштаб/anchor и attackIds. createEnemyInfoFromAsset в src/enemies/enemy.ts проверяет данные и ссылки на атаки, создаёт неизменяемый EnemyInfo. Пять Enemy делят один Info и имеют независимое состояние. Изменение текущих HP/щита принадлежит Enemy; урон сначала расходует щит. Ноль HP означает смерть.

assets/attacks/test-attack.json → src/enemies/attack.ts: неизменяемая тестовая AttackInfo, только typeId и имя. Выполнение атак и урон атаки не реализованы.

Корневой assets/images содержит test1.jpg (герой), tes2.jpg (противник), testeffect.jpg (горение). src/presentation/images.ts разрешает пути ассетов; esbuild встраивает JPG как data URI для HTTP и file://. Для нового изображения добавить импорт в этот реестр. Игровые данные не зависят от Pixi; живые текстуры/спрайты принадлежат main.ts.

Общее представление src/enemies/view.ts предоставляет текущие/базовые HP и щит, визуальные настройки и статусы. Над изображением: зелёная полоска HP, синяя щита (доля от базы, ограничена 100%; нулевая база даёт пустую полоску). Над ними иконки активных статусов до 16px до масштаба композиции. Выбранный Enemy обведён белым. Футер содержит debug-команды и параметры выбранного.

IStatusEffect содержит typeId, name, imageUrl и Tick. Каждый эффект — отдельный скрипт. Burning использует images/testeffect.jpg, наносит 3 урона за тик. Повторное наложение складывает длительность. В начале общего хода статусы обрабатываются в порядке первого наложения, после тика срок уменьшается, истёкшие удаляются. Смерть снимает статусы. Иконки исчезают вместе со статусами; сохранение хранит ID и длительность, изображение восстанавливается из справочника.

Сохранения schemaVersion 2 используют gamejam.enemies.v2. Старые NPC-сохранения не мигрируют; ранее созданные enemy-сохранения сохраняют исходный состав. Будущий порядок боя: статусы → атака игрока → атаки живых противников; сейчас есть только debug-команды.

## Изменение ассета

1. Изменить assets/enemies/test-enemy.json: parameters содержит ровно health и shield, без дублей; HP > 0, щит >= 0. typeId enemy.trainee сохраняется ради совместимости существующих сохранений.
2. visual.image задаётся относительно корневого assets, например images/tes2.jpg. Масштаб положительный, anchor.x/y в диапазоне 0…1; точка (0.5, 1) означает середину нижней границы изображения. Для новой картинки добавить импорт в src/presentation/images.ts и запись происхождения в assets/RESOURCE_REGISTRY.json активной версии.
3. attackIds содержит ссылки на AttackInfo из src/enemies/attack.ts. Новая JSON-запись сама не попадает в каталог: её нужно импортировать и зарегистрировать. Неизвестные ID отвергаются при создании EnemyInfo.
4. Для нового статуса реализовать IStatusEffect отдельным скриптом, указать imageUrl, зарегистрировать в status-effects/catalog.ts и добавить картинку в presentation/images.ts. Иконки выводятся в порядке наложения.
5. Выполнить штатные проверки и осмотреть сцену в настольном браузере. HTTP-preview и offline HTML создаются из одних исходников; редактировать сборку вручную нельзя.

При добавлении нового типа противника расширить каталог и разрешение typeId в loadSession: сейчас загрузка поддерживает только тестовый тип. JSON не хранит текущие HP/щит, длительность статусов, выбор и живые Pixi-объекты.

## Совместная сцена

Инвентарь расположен отдельным блоком рядом со сценой. Переходы его стадий не запускают атаки Enemy. Hover-карточка противника использует тот же createNPCView, что полоски и debug-панель; её контроллер принадлежит presentation/hover-card.ts. История восстановления старого экрана в INVENTORY.md относится к этапу до объединения; актуальная сцена использует изображения и пять Enemy.

Проверки объединённой версии и их ограничения: [SCENE_ASSETS](../qa/SCENE_ASSETS.md).
