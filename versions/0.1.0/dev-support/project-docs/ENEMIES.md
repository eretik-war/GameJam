# Противники и статусы

## Каталог и экземпляры

Корневые assets/enemies/test-enemy.json и camera-enemies.json задают четыре типа камер: enemy.trainee (розовая; прежний ID сохранён), enemy.camera.teal, enemy.camera.blue, enemy.camera.gold. Пока все четыре — наземные стрелки с прежними HP/щитом и attack.test. EnemyInfo содержит имя, role, замороженные числовые Parameters, Placement и attackIds. Placement — объект TypeEnemyPlacementParameter.Layer + Value из TypeBattleLayer (ground/air); placement.ts проверяет значение. Это статическое свойство типа.

src/enemies/enemy.ts владеет загрузкой, каталогом, getEnemyInfo и createEnemyFromInfo. Enemy хранит instance ID, ссылку на общий Info, независимые текущие параметры и статусы. ChangeParameter/TakeDamage владеют изменением HP/щита; урон сначала расходует щит. Ноль HP означает смерть. Игровые данные не зависят от Pixi.

assets/attacks/test-attack.json → src/enemies/attack.ts остаётся записью typeId/имени. Опубликованная атака из a82415c перенесена в EnemySession.Attack: расчёт урона принадлежит Hero, ответные удары/ход — сессии. Параметры героя — assets/heroes/player.json → domain/hero.ts. HeroInfo использует тот же неизменяемый справочник HP/щита, Hero наследует владельца параметров/статусов Enemy. Отдельный замороженный heroCombatInfo хранит типизированные базовые величины урона; ItemInfo.attackBonus добавляется один раз от активных слотов.

## Модульное представление

assets/enemies/camera-visuals.json — единственный источник размеров камер, PNG, точек крепления и модулей. Каждый вариант хранит собственный список attachments: детали можно добавлять/снимать независимо от других типов. src/enemies/visual-info.ts проверяет ссылки, совместимость роли/слоя и замораживает вложенные VisualInfo, связанные с игровым Info через typeId. Сокеты: underside, top, rear, lens. Пока заполнен только underside: shooter-leg допускается только для role=shooter и ground. Pivot/scale и socket повторяют предоставленную сборку. Исходники — [art/enemies](../art/enemies/README.md).

createEnemyVisualLayout рассчитывает части и полные границы по общей политике. presentation/enemy-visual.ts использует результат для Pixi-сцены и DOM-иконки debug-панели; tools/preview-enemies.mjs использует тот же resolver и компоновщик. Живые спрайты, текстуры, события и lifecycle принадлежат renderer/main.ts. Собранные PNG не дублируются в runtime: камера и ножки остаются отдельными частями.

Корневой assets/images/enemies содержит четыре camera-*.png и shooter-leg.png. Камеры вырезаны с сохранением пикселей/alpha; общий canvas не обрезает жёлтый вариант. test1.jpg остаётся героем. Статусы используют fire.jpg, blindness.png, stun.jpg и regeneration.png. Прежние tes2.jpg/testeffect.jpg сохранены, runtime их больше не загружает. presentation/images.ts разрешает пути; tools/build.mjs встраивает JPG/PNG как data URI для HTTP и file://.

src/enemies/view.ts предоставляет одну карточку текущих/базовых HP/щита, размещения, роли и статусов. Над полным силуэтом: зелёная полоска HP, синяя щита, выше иконки статусов. Доли ограничены 100%; нулевая база даёт пустую полоску. Выбранный Enemy обведён белой рамкой; hit-area включает голову и ножки. Hover использует тот же createNPCView. Фон обновлён предоставленным battle-location.jpg 1920×1080; он остаётся первым неинтерактивным спрайтом с заполнением cover. Absolute-наложение инвентаря и общий контракт MOBILE_UI_ASSETS сохраняют геометрию сцены/юнитов.

## Точки спавна

assets/enemies/spawn-points.json сохраняет исходные нормализованные координаты. spawn-1 (0.53, 0.30) и spawn-2 (0.75, 0.30) — air. spawn-3 (0.91, 0.50), spawn-4 (0.53, 0.75), spawn-5 (0.75, 0.75) — ground. Интерпретация разметки пользователя: правая и две нижние позиции наземные, верхние воздушные.

SpawnPointInfo имеет собственный параметр TypeSpawnPointParameter.Layer + Value TypeBattleLayer. spawn.ts владеет справочником и canSpawn/spawnEnemy: несовпадающий слой или занятая точка — ошибка. EnemySession владеет связью instance ID → spawn-point ID; renderer берёт координаты оттуда вместо выбора по индексу массива.

Новая сцена занимает три наземные точки (enemy-3/4/5) розовым, бирюзовым и голубым типами. Жёлтый готов в каталоге/preview. Воздушных типов в runtime пока нет, две воздушные точки пусты. Четыре визуала не означают четыре одновременно занятых наземных места.

## Статусы и сохранение

IStatusEffect содержит typeId, name, imageUrl и Tick. Burning использует images/fire.jpg и наносит 3 урона за тик. Blindness даёт 50% промаха через Enemy.CanAttack, Stun запрещает атаку до следующего BeginTurn, Regeneration восстанавливает 3 HP с ограничением базовым максимумом. Каталог содержит отдельный неизменяемый экземпляр каждого типа. Debug-кнопка случайно выбирает один из четырёх эффектов: stun на 1 ход, остальные на 3.

Повторное наложение складывает длительность. В начале общего хода статусы обрабатываются по порядку наложения, затем срок уменьшается и истёкшие удаляются. Смерть снимает статусы. Сохранение хранит ID эффекта и длительность. EnemySession.Attack вызывает CanAttack до тика/истечения статусов, после действия героя живые развёрнутые враги отвечают, затем обрабатываются статусы героя и ход врагов.

schemaVersion 2 и ключ gamejam.enemies.v2 сохранены. Enemy сохраняет typeId, ID и состояние; сессия добавляет spawnPointId (null — резерв) и состояние hero. loadSession восстанавливает четыре типа через каталог, отдельно Hero через его Info, проверяет параметры/статусы/ID и размещения до замены текущей сессии. Старые v2 без hero получают исходного героя и сохраняют свой состав противников.

Старые v2 без spawnPointId сохраняют исходный состав, выбранного, ход и значения. Подходящие точки назначаются с приоритетом выбранного; лишние наземные экземпляры остаются в сохранённом резерве. Отдельного UI резерва нет, EndTurn обрабатывает прежний состав. Старые NPC-сохранения не мигрируют. Инвентарь не входит в enemy-save.

## Изменение ассета

1. Добавить игровой JSON и зарегистрировать его в enemyCatalog. parameters содержит ровно health/shield без дублей, HP > 0, щит >= 0; placement/role и ссылки attackIds проверяются загрузчиком.
2. Добавить VisualInfo с тем же typeId в camera-visuals.json. Состав/размеры/сокеты редактировать здесь, без копий формулы в main или CURRENT_STATE. Изображение зарегистрировать в presentation/images.ts и RESOURCE_REGISTRY активной версии.
3. Спавнить совместимые типы через spawn.ts и сохранять связь в EnemySession. Начальная позиция справочника не является состоянием EnemyInfo.
4. Для статуса реализовать отдельный IStatusEffect, зарегистрировать в status-effects/catalog.ts, добавить изображение в общий реестр.
5. Выполнить npm run check, собрать preview и проверить desktop HTTP/file. Текущие результаты — [MODULAR_ENEMIES](../qa/MODULAR_ENEMIES.md); прежняя сцена — [SCENE_ASSETS](../qa/SCENE_ASSETS.md).

## Опубликованная атака в модульной сцене

Источник — commit a82415c. В бою клик по NPC вызывает Attack, в подготовке/награде боевого действия нет. Доступна ближайшая живая колонка по x реальной точки спавна; порядок массива NPC не определяет расстояние. После её уничтожения доступна следующая. Резерв не выбирается целью и не отвечает. Начально выбран ближайший enemy-4. Смерть героя блокирует дальнейшие атаки.

Hero.AttackDamage складывает базу из heroCombatInfo и attackBonus активных ItemInfo. Значения исходного commit сохранены: герой 1000 HP/20 щита, база урона 12, бонус предмета 2, ответ врага 5. После действия героя отвечают оставшиеся живые развёрнутые враги, затем герой.BeginTurn и EnemySession.EndTurn. Герой и NPC используют общий createCombatantView/createCombatIndicators; createNPCView добавляет только модульную композицию камер, поэтому герой не попадает в каталог деталей NPC.

Перенесено разрешение менять экипировку в бою и видеть карманы вне выбора награды. Debug скрыт и открывается D, кнопка «Дать герою 1 HP» сохранена из опубликованной реализации. Проверки объединения — [COMBAT_INTEGRATION](../qa/COMBAT_INTEGRATION.md).
## Воздушная поддержка — 2026-10-31

Каталог assets/enemies/healers.json сохраняет четыре стабильных typeId enemy.healer.magenta/teal/blue/gold. Все имеют 3 HP, 16 щита, воздушный слой, роль healer (общее представление «Поддержка»), пустые attackIds. Они никогда не атакуют героя, даже если поддерживать некого.

Розовый восстанавливает 3 HP живому развёрнутому союзнику, кроме себя. Бирюзовый восстанавливает 3 щита до базового максимума, также кроме себя. Приоритет — минимум текущего восстанавливаемого параметра, затем постоянный порядок spawnPoints. EnemySession.TryHeal выбирает цель непосредственно перед каждым действием. Оглушение/ослепление проверяются до активного восстановления.

Жёлтый постоянно усиливает исходящий урон атакующих союзников в 1,5 раза. Синий делит весь входящий урон противников (включая собственный и горение) на 1,5. EnemySession разрешает ауры от живых развёрнутых источников; одинаковые ауры не складываются. Они не расходуют ход и действуют при оглушении источника, исчезают сразу после его смерти. На каждом попадании Enemy.TakeDamage читает назначенную сессией политику; щит поглощает уже уменьшенный урон. Дробные значения не округляются. Регенерацию ни один тип поддержки больше не накладывает; общий статус регенерации остаётся доступен другим механикам.

SupportParameters — неизменяемые Parameter с отдельным TypeSupportParameter; тип/величина проверяются на границе JSON. Представление общих карточек читает те же параметры. Старые typeId сохранены, загрузка восстанавливает ссылки на актуальный каталог; сохранённые HP выше нового максимума отвергаются общим валидатором сохранений.

Корпус и цветной пропеллер остаются отдельными PNG; общий resolver VisualInfo используется сценой, карточками и preview. Источники пользователя — art/enemies/healer-*-source.png; извлечение — tools/extract-healer-parts.ps1. battle-1 показывает розового и бирюзового, battle-2 синего и жёлтого. Standalone createSession остаётся наземным debug-fixture.

## Щитовики — 2026-10-31
assets/enemies/guards.json добавляет enemy.guard.chair и enemy.guard.tracks: ground, роль guard, на стульчике 20 HP/50 щита, на гусеницах 50 HP/50 щита; общий ответный удар 5 (аура жёлтого применяется как к другим атакующим). Модульные детали guard-body/chair/tracks/shield предоставлены пользователем, зарегистрированы в images.ts/RESOURCE_REGISTRY. Единый createEnemyVisualLayout сохраняет полные bounds при скрытом щите; renderer пропускает только невидимую деталь, не сдвигая корпус/полоски/зону попадания.

EnemySession.CanTarget сначала определяет ближайшую живую колонку, затем среди неё активных щитовиков. Если они есть, можно атаковать любого из них; недоступный щитовик задней колонки/резерва не влияет. После разрушения доступны все живые цели ближайшей колонки, последующие колонки остаются закрытыми.

Enemy владеет guardActive и guardRecoveryTurns: 0 — готов; -1 — шкала щита пуста; переход 0 щита → положительное значение ставит счётчик 2. В конце раунда восстановления он уменьшается до 1, после следующего полного хода до 0. Пока счётчик положителен, провокация и изображение щита отключены. Новое разрушение сбрасывает ожидание. Любое изменение щита через ChangeParameter, включая TakeDamage/бирюзового, проходит эту политику. В Save v2 добавлено необязательное состояние guardRecoveryTurns только для щитовиков; загрузчик проверяет диапазон/совместимость со шкалой. Старые saves без поля получают готовый щит при положительной шкале, сломанный при нулевой.

battle-1 показывает стульчик вместо первой камеры, battle-2 — гусеницы; поддержка сохранена. Модельные проверки — tests/guards.test.ts, браузер — tools/verify-guards.mjs.

Ножки наземных камер заменены на четыре цветных роботизированных модуля shooter-leg-magenta/teal/blue/gold. Единый источник геометрии — camera-visuals.json; исходный лист robot-legs-source.png и метаданные вырезания находятся в art/enemies. Воспроизводимое извлечение — tools/extract-robot-legs.ps1. Старый shooter-leg сохранён как неиспользуемый ресурс. Характеристики и игровые ID камер не менялись.

## Роботы-боссы и возврат обычных ножек — 2026-10-31
У четырёх обычных камер восстановлен исходный модуль shooter-leg; характеристики остаются 30 HP/8 щита/5 урона. Четыре роботизированных цветных комплекта предназначены новым enemy.boss.magenta/teal/blue/gold из assets/enemies/bosses.json: роль boss, ground, 75 HP/20 щита, множитель урона 2,5 (12,5 без аур). Цветовые варианты имеют одинаковую механику.
EnemyInfo.CombatParameters хранит замороженный Parameter<TypeEnemyCombatParameter.DamageMultiplier>; Enemy.damageMultiplier разрешает значение, AttackSteps использует его один раз вместе с общей аурой жёлтого. Карточка читает те же CombatParameters. VisualInfo связывает корпуса и роботизированные ноги по typeId, модули допускаются только для boss. Сохранение восстанавливает новые typeId через общий каталог без новой схемы. В существующие уровни боссы не добавлены; доступны в каталоге и через создание/сохранение сессии. Исходные ресурсы обычных ножек сохранены ранее и переиспользованы без перерисовки.
