# Архитектура 2D-игры

## Слои

domain — состояние, правила действий, каталоги/фабрики, параметры и сериализация; не импортирует Pixi или DOM. presentation — общее вычисленное представление, форматирование, визуальные справочники по typeId. main/controller связывает ввод с командами модели и обновлением UI. Pixi stage хранит живые объекты по instance ID. tools собирает артефакты, vendor содержит точный движок.

Один Info описывает тип. Entity имеет собственный id, ссылку на Info и текущее состояние. VisualInfo использует тот же typeId; не связывать по имени картинки, переводу или позиции в массиве. Живые sprites, callbacks, подписки и selectedId в Info не кладутся. Параметры — объекты с enum и Value. Детали: локальные контракты standards.

## Новый предмет/инвентарь

Сначала найти общий каталог и фабрику. ItemInfo содержит неизменяемую базу/статические ссылки; Item — id, typeId, качество, количество, износ. Слот связывает владельца с instance ID предмета. В экипировке и сумке не создавать две независимые копии одного предмета. Правила stack/массы/занятости и транзакции переноса определяет игра. Проверять действие целиком до изменения: недопустимый перенос не теряет и не дублирует предмет. Карточка, магазин и бой читают одну evaluated view/политику взаимодействий.

## Пошаговые действия

Рекомендуемая отправная точка: команда → проверка допустимости → одно изменение состояния → события/общее представление → анимация. Правила хода не зависят от FPS или конца tween. Если понадобится случайность/replay, использовать явный seed и версию баланса/каталога; не брать случайные значения заново при перерисовке. Это направление для будущей игры, не реализованный полноценный боевой движок.

## Сохранения и платформа

Сохранять schemaVersion, instance/type IDs и необходимое состояние. Загрузку полностью проверить до замены живой сессии. Миграция схемы явная; не сбрасывать прогресс молча. SDK, облачный транспорт, реклама, звук/visibility должны иметь владельца lifecycle и не проникать в domain. Точки рекламы и награды — продуктовые решения, не свойства движка.

## Владельцы демо

NPCInfo — npc.ts; текущее Value — NPC.ChangeParameter; ход/выбор — GameSession; загрузка — loadSession; общие характеристики для двух представлений — createNPCView; sprites/подписки/resize — main.ts. Полная карта: CODE_MAP.md. Для большого мира заменить полную перерисовку демо обновлением объектов по id; делать это после измерения, не вводить лишние сущности заранее.

При добавлении нового семейства параметров объявить отдельный enum Type… в parameters.ts и включить его в ParameterType. Generic сохраняет конкретный enum владельца; сырые строки и enum чужого домена проверяются тестом компиляции tests/enum-types.ts. Не расширять ParameterType до string ради обхода ошибки.
