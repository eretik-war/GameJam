# Последовательность сцен

Два вида сцены: бой и катсцена. Цепочка — assets/campaigns/main.json. Наполнения assets/encounters/battle-1.json и battle-2.json сохраняют статические шаблоны для preview/валидации и задают фон; состав кампании формируется CampaignSession из существующего enemyCatalog. Пути assets относительно корня проекта.

Объединённый маршрут: intro → fight-1 → memory-2 → fight-2…fight-4 → interlude (memory-3) → fight-5…fight-8 → fight-2-repeat (девятый бой) → outro → finale. Сохранены локальные озвученные катсцены и девять боёв входящей версии; рестарт возвращает intro. ID врага включает шаг и точку спавна.

Количество врагов растёт по общему порядковому номеру боя и ограничивается числом совместимых мест. После объединения каталогов: 1 → 2 → 3 → 4 → 5 → 5…; три наземные точки для камер/щитовиков и две воздушные для поддержки. Катсцены рост не сбрасывают. Тип каждого врага независимо и равновероятно выбирается из всего совместимого enemyCatalog, в том числе после достижения предела; повторы допустимы. Лимит выводится из spawnPoints/canSpawn, не дублируется в UI. Точки заполняются от ближайшей колонны, резерв не создаётся. Фабрика выбирает первую реально атакуемую цель через CanTarget; активный щитовик в той же колонке имеет приоритет над воздушной поддержкой. Info/шаблоны неизменяемы, характеристики не копируются в кампанию.

Владельцы: domain/campaign.ts — цепочка, герой, создание боёв; EnemySession — бой/расстановка; InventorySession — предметы/награды; CutsceneController — реплики и ввод; presentation/scene-transition.ts — чёрный слой и fade; main.ts — интеграция и трёхсекундный таймер. Наполнения не дублируют характеристики EnemyInfo. Фоны разрешаются общим presentation/images.ts. Новые ресурсы нужно зарегистрировать там.

Победа проверяется после действия: герой жив, все противники мертвы. Награда открывается один раз. Выбор предмета запускает ожидание 3000 мс; при полных карманах то же делает разрешённый отказ от награды. Экипировку можно менять в ожидании. Затем 400 мс затемнения, смена сцены в полной темноте, 400 мс появления. Изображения декодируются перед появлением. Во время перехода ввод приложения, включая D, заблокирован. Последняя реплика остаётся на экране до следующего нажатия. После конца списка показан экран завершения, зацикливания нет. Поражение не продвигает цепочку.

Герой (включая HP/щит/статусы) и инвентарь сохраняются между сценами. Перезапуск страницы начинает цепочку сначала. Существующие debug save/load сохраняют только снимок боя; загрузка другого шага блокируется, цепочка и инвентарь не сохраняются. Это не полное сохранение кампании.

Debug-просмотр из боя временно показывает тестовую катсцену и возвращает в тот же бой без продвижения. В катсцене D открывает меню с одной кнопкой выхода: для обычной катсцены это завершение текущего шага, для preview — возврат. Старую ручную кнопку завершения боя/старта подготовки в обычном прохождении скрыли.

Проверки: tests/campaign.test.ts — все девять боёв, рост/предел, выбор из полного каталога, независимость экземпляров, неизменность Info, герой, завершение, неверные ссылки/дубли. tools/verify-campaign.mjs — реальный маршрут HTTP/file, все пять ground/air-точек, награды, задержка/fade по часам браузера, debug preview и финальная ветка; --restart проверяет возврат к одному врагу и пустому инвентарю. `--sustain-hero` включает явный route-fixture: HP героя восстанавливаются между боями через validated debug load; это не проверка естественной выживаемости/баланса. verify-cutscene.mjs вызывает общий прогон. Отчёты — builds/campaign-chain-continue.json и campaign-chain-restart.json; снимки — campaign-intro.png, campaign-battle-2.png, campaign-battle-3.png, campaign-choice.png, campaign-finale.png.
