# Последовательность сцен

Два вида сцены: бой и катсцена. Наполнения — assets/encounters/battle-1.json (бирюзовая камера), battle-2.json (голубая и жёлтая камеры), assets/cutscenes/test.json (фон CutsceneTest и три реплики). Цепочка — assets/campaigns/main.json. Пути assets относительно корня проекта.

Порядок: катсцена → бой 1 → бой 2 → катсцена → бой 2 → катсцена → завершение. Каждый шаг имеет стабильный уникальный ID; повтор наполнения создаёт новых противников с ID шага. Каталоги неизменяемы, валидируются до запуска; точки появления обязательны, резерв не создаётся. Новые файлы подключаются в domain/campaign.ts, затем включаются в offline-сборку без сетевых запросов.

Владельцы: domain/campaign.ts — цепочка, герой, создание боёв; EnemySession — бой/расстановка; InventorySession — предметы/награды; CutsceneController — реплики и ввод; presentation/scene-transition.ts — чёрный слой и fade; main.ts — интеграция и трёхсекундный таймер. Наполнения не дублируют характеристики EnemyInfo. Фоны разрешаются общим presentation/images.ts. Новые ресурсы нужно зарегистрировать там.

Победа проверяется после действия: герой жив, все противники мертвы. Награда открывается один раз. Выбор предмета запускает ожидание 3000 мс; при полных карманах то же делает разрешённый отказ от награды. Экипировку можно менять в ожидании. Затем 400 мс затемнения, смена сцены в полной темноте, 400 мс появления. Изображения декодируются перед появлением. Во время перехода ввод приложения, включая D, заблокирован. Последняя реплика остаётся на экране до следующего нажатия. После конца списка показан экран завершения, зацикливания нет. Поражение не продвигает цепочку.

Герой (включая HP/щит/статусы) и инвентарь сохраняются между сценами. Перезапуск страницы начинает цепочку сначала. Существующие debug save/load сохраняют только снимок боя; загрузка другого шага блокируется, цепочка и инвентарь не сохраняются. Это не полное сохранение кампании.

Debug-просмотр из боя временно показывает тестовую катсцену и возвращает в тот же бой без продвижения. В катсцене D открывает меню с одной кнопкой выхода: для обычной катсцены это завершение текущего шага, для preview — возврат. Старую ручную кнопку завершения боя/старта подготовки в обычном прохождении скрыли.

Проверки: tests/campaign.test.ts (повтор, герой, завершение, неверные ссылки/дубли), tools/verify-campaign.mjs (весь маршрут HTTP/file, награды, задержка, fade, debug preview). verify-cutscene.mjs вызывает общий прогон. Снимки — builds/campaign-intro.png и builds/campaign-battle-2.png.
