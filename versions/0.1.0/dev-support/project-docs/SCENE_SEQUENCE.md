# Последовательность сцен

Два вида сцены: бой и катсцена. Цепочка — assets/campaigns/main.json. Наполнения assets/encounters/battle-1.json и battle-2.json сохраняют статические шаблоны для preview/валидации и задают фон; состав кампании формируется CampaignSession из существующего enemyCatalog. Пути assets относительно корня проекта.

Игра сразу начинается с боя. Порядок: бои 1–3 → катсцена intro → бои 4–6 → катсцена interlude → бои 7–9 → финальный выбор outro → finale либо плавный перезапуск с боя 1. intro — сохранённый ID первой промежуточной катсцены, не заставка при запуске. ID боёв — fight-1…fight-9, ID врага включает шаг и точку спавна.

Количество врагов растёт по общему порядковому номеру боя и ограничивается числом совместимых мест. Сейчас 1 → 2 → 3 → 3…: четыре наземных типа, три наземные точки; воздушных типов пока нет. Катсцены рост не сбрасывают. Тип каждого врага независимо и равновероятно выбирается из всего совместимого enemyCatalog, в том числе после достижения предела; повторы допустимы. Лимит выводится из spawnPoints/canSpawn, не дублируется в UI. Точки заполняются от ближайшей колонны, резерв не создаётся. Info/шаблоны неизменяемы, характеристики не копируются в кампанию.

Владельцы: domain/campaign.ts — цепочка, герой, создание боёв; EnemySession — бой/расстановка; InventorySession — предметы/награды; CutsceneController — реплики и ввод; presentation/scene-transition.ts — чёрный слой и fade; main.ts — интеграция и трёхсекундный таймер. Наполнения не дублируют характеристики EnemyInfo. Фоны разрешаются общим presentation/images.ts. Новые ресурсы нужно зарегистрировать там.

Победа проверяется после действия: герой жив, все противники мертвы. Награда открывается один раз. Выбор предмета запускает ожидание 3000 мс; при полных карманах то же делает разрешённый отказ от награды. Экипировку можно менять в ожидании. Затем 400 мс затемнения, смена сцены в полной темноте, 400 мс появления. Изображения декодируются перед появлением. Во время перехода ввод приложения, включая D, заблокирован. Последняя реплика остаётся на экране до следующего нажатия. После конца списка показан экран завершения, зацикливания нет. Поражение не продвигает цепочку.

Герой (включая HP/щит/статусы) и инвентарь сохраняются между сценами. Перезапуск страницы начинает цепочку сначала. Существующие debug save/load сохраняют только снимок боя; загрузка другого шага блокируется, цепочка и инвентарь не сохраняются. Это не полное сохранение кампании.

Debug-просмотр из боя временно показывает тестовую катсцену и возвращает в тот же бой без продвижения. В катсцене D открывает меню с одной кнопкой выхода: для обычной катсцены это завершение текущего шага, для preview — возврат. Старую ручную кнопку завершения боя/старта подготовки в обычном прохождении скрыли.

Проверки: tests/campaign.test.ts — все девять боёв, рост/предел, выбор из полного каталога, независимость экземпляров, неизменность Info, герой, завершение, неверные ссылки/дубли. tools/verify-campaign.mjs — реальный маршрут HTTP/file, три точки спавна, награды, задержка/fade по часам браузера, debug preview и финальная ветка; --restart проверяет возврат к одному врагу и пустому инвентарю. verify-cutscene.mjs вызывает общий прогон. Отчёты — builds/campaign-chain-continue.json и campaign-chain-restart.json; снимки — campaign-intro.png, campaign-battle-2.png, campaign-battle-3.png, campaign-choice.png, campaign-finale.png.

Финал (2026-10-31): outro использует отдельное assets/cutscenes/outro.json с фоном CutsceneTest и двумя репликами пользователя. На второй реплике обязательный выбор: «Стереть память» запускает общий SceneTransition (400 мс затемнения + 400 мс появления): в темноте CampaignSession.restart и InventoryController.reset сбрасывают кампанию, героя и инвентарь, затем открывается fight-1 с одним случайным врагом без перезагрузки страницы, «Жить дальше» продвигает в finale. assets/cutscenes/finale.json — отдельная сцена с finale.png и пустыми lines: диалог и переход по Enter/Пробел/D отсутствуют. Debug не обходит выбор. Проверка перезапуска: node tools/verify-campaign.mjs --restart.
