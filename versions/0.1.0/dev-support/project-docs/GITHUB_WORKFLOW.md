# GitHub и совместная работа

По запросу пользователя от 2026-10-30 используется публичный [eretik-war/GameJam](https://github.com/eretik-war/GameJam), ветка `main`. Репозиторий хранит исходники, документацию, package-lock и локальный vendor с лицензией. node_modules, рабочие файлы, backups, секреты .env/ключи и воспроизводимые HTML/манифесты сборки исключены через .gitignore. Публичный репозиторий не публикует игру на хостинг.

## Постоянное разрешение на отправку и статус каждого сообщения

Прямое поручение пользователя от 2026-10-30: после каждой завершённой доработки нейронка сразу запускает отправку в репозиторий, а каждое сообщение заканчивает фактическим статусом GitHub. Это постоянное явное разрешение на commit/push изменений текущей задачи; отдельно спрашивать «отправить?» не нужно. Правило распространяется на код, данные, ресурсы, инструменты и документацию, включая CURRENT_STATE. Оно заменяет прежнее требование отдельно поручать каждую отправку.

При каждом начале нового чата, ознакомлении с проектом и восстановлении после compaction прочитать этот раздел до работы. Он обязателен и для предметных задач, и для общего ознакомления. Одно чтение не создаёт изменений и не требует пустого commit.

После каждой завершённой доработки:

1. Просмотреть git status/diff, обновить CURRENT_STATE и выполнить требуемые проверки. В commit должны войти только изменения текущей задачи; чужие и незавершённые правки не включать.
2. Сразу выполнить `npm run sync:push -- "Содержательное описание доработки"` (на Windows можно npm.cmd). Команда сама запускает npm run check. Если в папке есть посторонние правки, вместо добавляющей всё команды использовать адресный git add нужных файлов, commit и обычный push после проверок.
3. До итогового ответа проверить успешность push и наличие отправленного commit в удалённой main. Локальный commit или успешная сборка сами по себе не подтверждают обновление GitHub. Сообщить SHA или ссылку на commit; результат CI указывать отдельно по факту проверки.

Последняя строка **каждого** сообщения пользователю, включая промежуточные обновления, ответы на вопросы и ознакомление:

- `Репозиторий обновлён: <короткий SHA и/или ссылка на отправленный commit>.` — только после подтверждённого push до этого сообщения.
- `Репозиторий не обновлён: <конкретная причина>.` — если после предыдущего сообщения отправки не было: идёт работа/проверка, только ознакомление без изменений, отправка запрещена пользователем, проверка не прошла, нет связи/доступа или возник конфликт. При наличии неотправленных правок явно указать, что они остались локально.

Нельзя подставлять успех в каждое сообщение автоматически. Если push не выполнен или не подтверждён, использовать второй вариант и назвать причину. При ошибке исправить её в рамках задачи и повторить безопасную отправку; при внешней блокировке сохранить работу и сообщить препятствие. Не обходить проверки и не применять force push/reset/clean/автоматический stash/rebase. Новое прямое указание «только локально», «без отправки» или «ничего не менять» имеет приоритет. Разрешение на commit/push не разрешает deploy, публикацию игры на площадке, создание новой версии или удаление старых копий.

## Первое подключение товарища

Владелец приглашает `rgweh` как collaborator. Товарищу нужно принять приглашение в GitHub, чтобы отправлять изменения прямо в этот репозиторий. Чтение публичного кода доступно без приглашения. Для push нужна собственная авторизация GitHub, например `gh auth login`, затем `gh auth setup-git`.

```sh
git clone https://github.com/eretik-war/GameJam.git
cd GameJam
git config user.name "Ваш GitHub-логин"
git config user.email "Ваш GitHub noreply email"
git config pull.ff only
npm ci
npm run check
npm run dev
```

GitHub noreply email можно взять в Settings → Emails. Локальные git config применяются только к этой копии. На Windows допустимо везде заменить npm на npm.cmd. После клонирования готовый HTML создаётся командой `npm run build:offline`; вручную копировать node_modules или воспроизводить диск C: не нужно.

## Ежедневная работа

Перед началом: `npm run sync:pull`. Нейронка после каждого законченного изменения выполняет отправку автоматически по постоянному разрешению выше. Команда для отправки:

```sh
npm run sync:push -- "Добавил выбор NPC с клавиатуры"
```

Команда получает информацию с GitHub, при необходимости обновляет чистую папку fast-forward, запускает `npm run check`, добавляет все неигнорируемые правки, создаёт commit с вашим описанием и отправляет main. Проверки, завершившиеся ошибкой, останавливают команду до добавления и commit. Уже подготовленные вручную изменения тоже входят в commit. Если другой участник успел отправить изменения, Git отвергнет несовместимый push; локальный commit останется сохранённым.

После push GitHub Actions запускает тот же `npm run check`: typecheck, модель, интеграционные тесты синхронизации, offline build и validate. Проверки также работают для pull requests. Автоматического deploy и объединения PR нет. Проверки main не являются обязательной защитой ветки: прямой git push может обойти локальную команду.

`npm run sync:status` показывает ветку, наличие локальных правок, опережение/отставание относительно последнего fetch и результат последней синхронизации. `npm run sync:pull` делает fetch сейчас. Для ручных команд состояния dirty/diverged/busy возвращают код 2, ошибка — 1.

## Автоматическое получение

На каждой Windows-машине отдельно:

```sh
npm run sync:auto:install
npm run sync:auto:status
```

Установщик регистрирует одну задачу Windows Task Scheduler с именем GameJam-Sync и суффиксом пути. Она стартует сразу и далее каждые 5 минут, работает скрыто с обычными правами текущего пользователя, когда он вошёл в Windows. Пароли и токены в проект не записываются; используется существующая авторизация Git. Настройка не зависит от открытого Codex и не вызывает модель. ExecutionPolicy Bypass применяется только к процессу запуска локального скрипта; общая политика Windows не меняется.

Автоматический шаг только получает origin/main и применяет fast-forward при чистой папке. Он не создаёт commits, не отправляет изменения, не делает reset/clean/stash/rebase, не переключает ветку и не разрешает конфликты. Одновременные проектные команды синхронизации блокируются общим lock. Git merge/rebase/cherry-pick/bisect также приостанавливают синхронизацию.

При dirty обновление ждёт завершения вашей работы. При diverged требуется ручное объединение. Отсутствие интернета не меняет исходники; следующая попытка будет через 5 минут. В .git/gamejam-sync/status.json хранится последний результат, в auto.log — вывод фонового запуска. Два одинаковых установщика для одной папки обновляют одну задачу. После переноса/переименования папки удалите задачу из старой копии и установите её в новой.

Отключить: `npm run sync:auto:remove`. На macOS/Linux работают ручные sync-команды; Windows-автоматизация туда не устанавливается.

Обновляются исходники. После изменения package-lock выполните `npm ci`; фон сам не запускает установку пакетов или присланный код. Запущенный dev-сервер пересобирает игру при обновлении страницы. Отдельный offline HTML пересоберите через `npm run build:offline`. Браузерный игровой прогресс GitHub не синхронизирует.

## Если работа разошлась

Если есть ваши незакоммиченные правки, сначала просмотрите их и сохраните локальным commit:

```sh
git status
git diff
git add --all
git commit -m "Сохранил свою работу перед объединением"
git fetch origin
git merge origin/main
```

При конфликтах вручную объедините затронутые файлы, затем `git add` этих файлов и `git commit`. После успешного объединения: `npm run sync:push -- "Объединил изменения"`. Не применяйте force push или сброс рабочей папки. Если нужно отменить незавершённое объединение, `git merge --abort` вернёт состояние до merge.

Делите подсистемы/файлы между участниками; общие enum, Info, save schema и зависимости согласовывайте. Для крупной работы можно использовать отдельную ветку и PR; автоматическая синхронизация намеренно работает только на main.
