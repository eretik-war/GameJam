# Боевые предметы: отдельное семейство и общий каталог

## Активная структура

Предметы **не обязаны описываться в одном файле**. Общими остаются контракт Info, каталог, фабрика экземпляров, расчёт и представление; определения семейств можно разносить по модулям.

- `src/domain/items.ts`: ItemInfo/Item, исходные линзы item.01–04 и модули item.05–08, объединённый `itemInfos`, проверка повторяющихся typeId, `getItemInfo` и единственная `createItemFromInfo`.
- `src/domain/combat-items.ts`: только новое боевое семейство item.09–12, строгий `TypeCombatItemTrait`, замороженный объект свойства `Type` + `Value` + описание. `createCombatItemInfos(ItemInfo)` получает общий конструктор; импорт ItemInfo здесь type-only, циклического runtime-импорта нет.
- `src/domain/combat-item-rules.ts`: суммирование свойств активных слотов, уклонение, перенос и расчёт усиленного удара. Формулы не повторяются в UI.
- `src/enemies/session.ts`: подключает эти правила к настоящему попаданию героя и каждому ответному удару. Промах/оглушение не активируют перенос.
- `src/enemies/enemy.ts`: `TransferNegativeStatus` переносит один статус через владельцев обоих экземпляров, а `TakeDamage` остаётся владельцем изменения HP/щита.
- `src/presentation/combat-item-visuals.ts`: представления нового семейства. `item-view.ts` объединяет их с исходными VisualItemInfo; общие createItemView/createItemIcon обслуживают награды, карманы, экипировку и drag.
- `entity-hover-cards.ts`: одновременно показывает прибавку урона и боевое свойство, а не прячет урон как у чистого пассивного модуля.

## Новые типы

Базовые значения принадлежат `combat-items.ts`; названия и карточки читаются из общего ItemInfo.

| typeId | Название | Действие в активном слоте |
|---|---|---|
| item.09 | Линза уклонения | +2 урона; 10% избежать вражеского удара вместе с его эффектом |
| item.10 | Линза переноса | +2 урона; при попадании 25% перенести один негативный эффект с героя на цель |
| item.11 | Линза разрушения щитов | +2 урона; +25% к части удара по щиту |
| item.12 | Линза поражения | +2 урона; +25% к части удара по здоровью |

Перенос снимает с героя самый ранний из оставшихся негативных статусов, сохраняет его оставшуюся длительность и не переносит положительные эффекты. Если на цели уже есть такой статус, длительности складываются по существующему AddStatus. Нет переноса на мёртвую цель или после промаха; ошибка переполнения длительности не удаляет исходный статус. Перенесённый эффект тикает в обычном EndTurn, как остальные эффекты.

Уклонение проверяется отдельно для каждого действительно попавшего ответного удара. Оно не отменяет периодический урон уже наложенного горения. Карманы ничего не усиливают; снятие предмета прекращает его действие на следующем ударе. Копии суммируют прибавки и свойства, вероятности ограничены 100%.

### Щит и остаток удара

В `equippedAttackDamage` D — база героя плюс прибавки надетых предметов, S/H — суммы бонусов по щиту/здоровью. Щит поглощает `min(щит, D × (1 + S))`; из базы списывается поглощённое, делённое на `(1 + S)`. Только оставшаяся база умножается на `(1 + H)` для здоровья. Суммарное воздействие передаётся в обычный TakeDamage: усиление не применяется к остатку второй раз. Дробные значения сохраняются без округления.

## Выпадение и расширение

FinishCombat использует **объединённый itemInfos**, а не свой ручной список: выбирает три разных типа один раз. Поэтому всё новое семейство участвует в случайных наградах после реальной победы. ChooseReward использует прежнюю фабрику и выдаёт отдельный instance ID. Исходные восемь типов сохранены.

Чтобы добавить следующее семейство, определить Info отдельно, подключить его к itemInfos и VisualItemInfo к общему представлению. Проверить совпадение наборов typeId и отсутствие дублей. Не создавать второй пул наград, отдельные предметы для UI или формулу в карточке. Перед параллельной работой согласовать маленькие изменения объединяющих файлов; отдельные файлы не защищают от чужого удаления/перезаписи подключений.

По уточнению пользователя item.09–12 используют отдельные предоставленные PNG, а не изображения старых линз или модулей: item.09 — голубой (IMG_5547), item.10 — розовый (IMG_5549), item.11 — золотой (IMG_5546), item.12 — бирюзовый (IMG_5548). Оригиналы сохранены побайтно в dev-support/art/items/combat; tools/prepare-combat-item-icons.py только обрезает прозрачные поля и пропорционально масштабирует с сохранением alpha до 128×128. Runtime: assets/images/items/item-combat-*.png. Старые изображения item.01–08 не менялись. SHA и подготовка записаны в combat-icons-extraction.json и RESOURCE_REGISTRY. Проверка соответствия и неизменных старых назначений — tests/combat-item-icons.test.ts. Размеры слотов и геометрия сцены не менялись. Инвентарь между запусками по-прежнему не сохраняется; schemaVersion/старые ID сохранений боя не изменены.
