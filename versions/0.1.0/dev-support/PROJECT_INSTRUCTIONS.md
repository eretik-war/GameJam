# Постоянные правила GameJam

Проект для 2D PixiJS-разработки. Источник разрешений — запрос пользователя; AGENTS задаёт короткий рабочий маршрут. Внешняя общая система не требуется: локальные standards — переносимый снимок с SOURCE_PROVENANCE.json. При расхождении новое прямое указание пользователя важнее прежнего примера; уточнять только существенную неоднозначность.

- Логика и сохранения в domain, картинки/DOM/Pixi — в presentation/main. Один владелец каждого изменения; общие view/формулы/реакции переиспользуются всеми окнами.
- Новая сущность сразу использует Info/Entity, стабильные typeId/id и объекты параметров. Копируются изменяемые записи состояния, а не общие справочники. Проверять внешние данные на границе.
- Фиксировать только принятые решения в DECISION_LOG; гипотезы — BACKLOG; текущую работу — CURRENT_STATE; историю — VERSION. Архитектуру и формулы не копировать в состояние/роутеры.
- Рабочая папка версии — из манифеста. Новую версию не создавать для каждой мелкой правки без решения. Критические старые файлы перед большой заменой сохранять в backups; релизные артефакты — в versions.
- Изменять исходники, не vendor/node_modules/генераты. Движок и инструменты закреплены точными версиями; обновление требует согласованной причины и проверок. Не использовать CDN/сетевой fallback в offline.
- Пока работаем только над компьютерной версией игры. Соблюдать [MOBILE_UI_ASSETS](project-docs/MOBILE_UI_ASSETS.md): интерфейс и проверки для настольного браузера с мышью и клавиатурой; мобильная адаптация и мобильное тестирование не требуются до отдельного поручения пользователя. Атласы, учёт GPU-памяти, ~10 МБ как бюджет простой игры, происхождение/лицензии остаются применимы. Музыку не генерировать.
- Пока площадки публикации не выбраны, не добавлять SDK/монетизацию. Внешняя публикация, реальные платежи и удаление не следуют из команды собрать/исправить.
- Для двоих: делить работу по стабильной ответственности, перед общей правкой обозначать затронутые контракты/потребителей; передачу сопровождать проверками и checkpoint.
- Постоянное разрешение пользователя: свои завершённые доработки после проверок отправлять commit/push. Проверка репозитория и итоговый статус — при завершении задачи либо по прямому запросу обновить/отправить изменения. Промежуточные сообщения без обязательной Git-строки; основное внимание локальным дополнениям. При входе/восстановлении чата читать [каноническое правило и исключения](project-docs/GITHUB_WORKFLOW.md#auto-push).
