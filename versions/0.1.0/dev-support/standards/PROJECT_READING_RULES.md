# Чтение проекта по намерению пользователя

Принято пользователем 2026-10-30 для WebGames. Это canonical правило выбора объёма знакомства; постоянные архитектурные контракты остаются у своих владельцев.

## Общий вход

Всегда учитывать применимые AGENTS. Кратко прочитать stable READ_FIRST, определить активную версию и нужный индекс. Индексатор здесь — DOCUMENTATION_INDEX и CODE_MAP (или их проектные аналоги), а не обязательный отдельный сервис. Использовать rg/поиск имён перед массовым чтением. Не читать node_modules, vendor, bundles, backups, историю и соседние проекты без причины.

## Два режима

1. **Общее знакомство.** Если пользователь просто сказал «ознакомься с проектом», прочитать весь базово необходимый набор, явно отмеченный в его READ_FIRST/индексе: постоянные правила, текущее состояние, архитектуру, запуск, проверки и ограничения. Завершить кратким описанием состояния и границ. Это не разрешение менять игру.
2. **Конкретное направление.** Если пользователь обозначил цель чата («работаем над инвентарём», «исправь адаптацию», «настрой сборку»), не проводить полный onboarding. После короткого входа и индекса читать только код, правила, состояние и проверки этой области. Общие основы Pixi/сборки нужны, если задача их использует; простая правка текста не требует их полного чтения.

## Расширение области

Индекс остаётся навигацией на протяжении задачи. Если обнаружена зависимость вне первоначальной области, открыть соответствующий раздел индекса и контракт **до изменения**. Например: NPC → параметры/Info; перемещение предметов → владельцы/сохранение; новый экран → общее представление/взаимодействия; реклама → платформа/lifecycle. Дочитывать только нужную границу, а не весь проект заново.

Режим чтения не отменяет применимые запреты, пользовательское разрешение, точный lock или проверку FOUNDATION_UPDATES один раз перед изменениями. Не требовать у пользователя подтверждения уже разрешённой задачи только из-за смены читательского маршрута.

## Ответственность документов

READ_FIRST содержит короткий маршрут и указатель активной версии. Индекс указывает назначение, триггер чтения и базовый набор. CODE_MAP указывает владельцев, потребителей, входы, generated-границы и тесты. CURRENT_STATE хранит текущую работу; общие формулы и модели в нём не дублируются.
