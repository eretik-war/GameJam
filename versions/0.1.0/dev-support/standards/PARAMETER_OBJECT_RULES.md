# Контракт объектов параметров

Принят пользователем 2026-10-30. Применять вместе с [INFO_OBJECT_RULES.md](INFO_OBJECT_RULES.md) при проектировании новых параметров, эффектов, NPC и сохранений. Формат данных зависит от языка; смысл одинаков.

## Параметр — типизированный объект

Параметр хранит ключ из конкретного enum и Value. Пример: Parameter<TypeNPCParameter> { Type: TypeNPCParameter.Health, Value: 100 }. Это одна запись массива Parameters, а не набор несвязанных полей health/armor/damage и не строковый словарь без проверки.

Префикс Type в названиях TypeParameter, TypeNPCParameter явно обозначает тип/вид параметра — перечисление допустимых ключей. Каждый домен имеет свой строго типизированный enum; ключ действия нельзя случайно подставить вместо ключа здоровья. Не сводить все enum к string/number/any. Стабильные значения enum используются в сохранениях, не зависят от порядка строк или перевода. В JSON тип восстанавливается только после runtime-проверки по разрешённому набору.

Пример пользователя на C#:

```csharp
public enum TypeParameter { AllReqAction, LastPerformed, FirstPerformed }
public class RestoreParameter {
    public TypeParameter UseTypeParameter; // Какой параметр изменить
    public float Value; // На сколько прибавить при активации
}
```

Это enum параметров действий. Для здоровья, брони и урона нужен отдельный TypeNPCParameter. RestoreParameter описывает воздействие на параметр; его Value — прибавка, а не новое абсолютное значение и не второй экземпляр параметра цели. В TypeScript допустим generic RestoreParameter<TEnum>, сохраняя конкретный enum на каждом месте использования.

## Info и игровой экземпляр

NPCInfo содержит замороженный массив базовых объектов параметров; вложенные записи тоже неизменяемы. Фабрика NPC сохраняет общую ссылку на NPCInfo и создаёт отдельные изменяемые объекты текущих параметров. Два NPC одного типа не делят изменяемый массив или записи. База и текущее значение различаются явно; не хранить параллельно npc.health и Parameters[Health] как два источника истины.

NPC владеет ChangeParameter(TypeNPCParameter, delta) или эквивалентом: перечисляет свои параметры, находит запись с совпадающим enum и изменяет её Value. ApplyRestore читает UseTypeParameter и Value воздействия и вызывает этот же метод. UI, эффект, экипировка и редактор используют единого владельца изменений. Не менять NPCInfo и не искать параметр по индексу массива. Если объём обоснованно требует ускорения, производный индекс не становится вторым владельцем значений.

## Проверки и границы

- На один enum-ключ в массиве максимум одна запись. Неизвестный ключ, отсутствующий обязательный параметр, дубль, NaN/Infinity — явная ошибка.
- Правила min/max принадлежат модели конкретного параметра/игры. Прибавка, установка, восстановление до максимума и временный модификатор различаются явно; не угадывать по имени поля.
- Изменение состояния обновляет все зависимые вычисления/окна через общую политику представления. Модификатор качества применяется к базе один раз.
- Сохранение содержит стабильные enum-ключи и текущие значения; при загрузке проверить схему, typeId, instance ID, полный набор параметров и допустимые диапазоны, затем восстановить через каталог/фабрику. Невалидную загрузку отвергать до замены текущего состояния.
- Проверить типовую несовместимость чужого enum на компиляции, неизвестные значения JSON, независимость копий, неизменность базы и round-trip сохранения.

Новым сущностям контракт применяется сразу. Документ не поручает массовую миграцию существующих игр и не разрешает сброс сохранений. Исполняемый пример находится в ../../src/domain/parameters.ts и ../../src/domain/npc.ts относительно этого документа.
