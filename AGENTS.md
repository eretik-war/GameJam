# GameJam — инструкции нейронке

Перед любой задачей и после восстановления контекста обязательно прочитать целиком [SYNC_TOOL.md](SYNC_TOOL.md), затем [READ_FIRST_LATEST_PROJECT.md](READ_FIRST_LATEST_PROJECT.md). Чтение инструкции не запускает команды. **GitHub пока приостановлен: только локальная работа до отдельного указания пользователя.** Активные пути — PROJECT_MANIFEST.json; зависимости — ENGINE_LOCK.json/package-lock.json. Индекс: [DOCUMENTATION_INDEX](versions/0.1.0/dev-support/DOCUMENTATION_INDEX.md).

## Выбрать объём чтения

- Если пользователь просто просит ознакомиться, прочитать весь базовый набор, перечисленный во входном документе.
- Если цель чата конкретная, прочитать короткий вход, индекс/нужный раздел CODE_MAP и только документы/исходники этой области. До выхода за неё вернуться к индексу и прочитать затронутый контракт. Не читать весь проект заранее.
- Применимые AGENTS, ограничения и locks обязательны. Искать через rg перед широким чтением. Исключать node_modules, vendor, builds, backups, work и историю из обычного поиска.

## Неизменные правила

- Пока разрабатываем только компьютерную версию игры: интерфейс под мышь и клавиатуру, проверки в настольном браузере. Подгонять интерфейс под мобильные устройства и тестировать мобильные размеры, ориентации или touch-ввод не нужно. Мобильный этап — только по отдельному поручению пользователя; подробности в MOBILE_UI_ASSETS.
- Инвентарь, награды и всплывающие карточки накладываются поверх существующих окон. Блок юнитов и зона боя сохраняют положение, размер и масштаб; не выделять под наложение место в раскладке. Каноническое правило и проверка — MOBILE_UI_ASSETS, раздел «Наложения поверх сцены».
- Info — общий неизменяемый справочник. Entity хранит instance ID и своё состояние. VisualInfo связан через typeId, живые Pixi/DOM-объекты принадлежат renderer.
- До изменения сущностей читать локальные INFO_OBJECT_RULES и PARAMETER_OBJECT_RULES из индекса. Параметр — объект enum Type… + Value; enum разных доменов не смешивать; изменение по enum через владельца Entity. Вложенные записи Info не мутируют.
- Одна формула/карточка/политика взаимодействий для всех окон. Сначала найти владельца и потребителей. Не дублировать значения в UI или CURRENT_STATE.
- Игровые данные не зависят от Pixi. Не редактировать vendor/собранный HTML вместо исходников. Версию движка не подменять на latest.
- GitHub сейчас отключён: без fetch/pull/push, удалённых проверок, CI-опросов и автосинхронизации, включая завершение задачи. Прежнее разрешение на отправку приостановлено. Локальные status/diff и адресный commit допустимы по необходимости для сохранности работы; чужие правки не включать. Возобновление — только по новому прямому указанию пользователя, без автоматического восстановления по времени. Канонический режим — GITHUB_WORKFLOW. Ясное поручение разрешает реализацию; идеи в обсуждении сами по себе её не поручают. Новая версия, deploy/публикация, удаление старых копий и общие миграции требуют отдельного решения.
- Проверять соразмерно риску. Перед передачей — typecheck, тесты модели, validate, offline build и браузерная проверка затронутого поведения. Команды находятся в RUN_COMMANDS.
- При передаче/compaction обновить CURRENT_STATE: цель, разрешение, решения, working set, проверки, риски, следующий шаг и артефакты.

## Инструменты и контекст

OpenCode необязателен. Если явно выбран, сначала читать локальный use-opencode-cli/SKILL.md, когда он доступен; иначе работать напрямую. Не создавать агентов/чаты без разрешения пользователя или применимого явного правила. Не делегировать продуктовые решения вспомогательному оператору.

Не запускать token counter после каждого сообщения; измерять по запросу или на границах крупных фаз/экспериментов. Не жертвовать проверками ради экономии контекста.
